    No developer words in the UI (CLV-63)¶

    Status: spec (release prep, epic calvin-354a). Frontend copy only, plus one small helper. Rules from 2026-10-30-settings-copy-audit.md §5: - say screen, page, source, plugin, Calvin (for the server); - never "backend", "frontend", "API", "instance", "config", "branch", "schema", "Healthy"; - no raw error text on the dashboard.

    Paths are under frontend/src/. "→ remove" means delete the element. Build after CLV-64 (theme tokens).

    1. Raw errors (fix once, everywhere)¶

    Today raw err.message / response.data.detail reaches the screen. On the wall that means "Network Error" or "Request failed with status code 500". Where: stores/images.js, calendar.js, webServices.js, config.js, keyboard.js (error.value = err.message), shown in PhotoSlideshow.vue:23; also WebComponentHost.vue:56, ClockBarItemsTab.vue:110, SecuritySettings.vue:105/145, useConfigForm.js:241.

    New helper utils/friendlyError.js: friendlyError(err, action) → one sentence:

    Case Text
    no response (network) Couldn't reach Calvin. Check that it's running and on the same network.
    401/403 You need to sign in as admin to {action}.
    404 That's no longer there. Reload and try again.
    409 That conflicts with an existing one. (callers may pass a specific line)
    422/400 with a string detail written for people (backend validation messages) that detail
    5xx / anything else Something went wrong on the Calvin server while trying to {action}.
    • Stores keep the raw error for logs (logError) and expose errorText from friendlyError.
    • On the dashboard, no error text at all: offline/stale states use the CLV-20 empty states and the ConnectionStatus pill (#172). Remove PhotoSlideshow.vue:23-24 ({{ imagesStore.error }}).
    • In Settings, a raw detail may appear only behind a Details disclosure (--fs-xs, --font-data, --ink-3) under the friendly line. Same for UpdatesTab.vue:69, 117.
