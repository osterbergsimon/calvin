    Frontend consistency audit (2026-10-31)¶

    Owner request: "we need a proper FE audit on things like the .btn issue; it's not scalable." Method: frontend/scripts/ui-audit.py parses every .vue <style> block and template (126 files, dev/ excluded) and counts hand-rolled versions of shared patterns outside components/ui/. "Distinct looks" means distinct combinations of background / border / radius / padding / font-size / weight, i.e. how many visual variants exist. The script is in the repo, so these numbers can be re-run and must only go down. Target components and rules come from the frontend doctrine.

    1. Summary¶

    Re-implemented components: 5 files build their own switch, 2 their own tabs, 4 their own modal and 3 their own popover or menu. 9 files implement role="dialog" separately: ConnectionStatus popover, ThemePicker, AdminSignInDialog, EmbedOverlay, HandoffOverlay, ActionPicker, ScreenRegionEditor, ProviderPicker, Settings.

    2. What this means¶

    • Every new feature re-solves "what does a button / box / error look like". With 39 button looks and 103 box looks, any new setting is guaranteed to differ from its neighbours. Specs can't prevent it, because there is nothing to point at.
    • Tokens didn't fix it. Most of these rules already use tokens. The variation is in which token and which combination. Shared components fix that; more tokens don't.
    • Overlays are a correctness risk, not just looks. 28 z-index values and 9 dialog implementations are how the OSK/dialog stacking bugs (CLV-9 review) happened. Each dialog also re-implements its own focus trap and Escape handling.

    3. Plan (maps onto the doctrine's migration)¶

    P1: the shared blocks, then the worst files. 1. Build in components/ui/, each with a gallery entry (ui-gallery.html) and unit tests: - Button (primary / secondary / ghost / danger / link; md / sm; icon; loading); - TextField; - InlineNote (tones); - Card; - ListRow; - Dialog (title, body, actions, scrim, focus trap, Escape, --z-dialog, OSK-aware via dialog-above-osk). 2. Add the lints with today's offenders as a shrinking allowlist: controlLint (buttons and inputs), roleLint (z-index, shadow, weight, duration literals and primitives), settingsNoStyle. 3. Migrate one category per PR, worst first (matrix below): Plugins (installer, InstanceModal, picker), the page editor and its inspectors, Screens, the sign-in dialog and lock screen, Security, System, Content, then the dashboard surfaces. Each PR deletes the file's local control styles and removes it from the allowlists, with before/after shots from the mocked e2e harness at 1280 and 390.

    P2: Dialog adoption for the 9 dialog implementations; EmptyState everywhere; headings to 3 roles; z-index, shadow, weight and duration to the fixed sets; one breakpoint set.

    P3: remaining badges to Tag; emoji → mdi; native controls wrapped.

    Done when ui-audit.py reports, outside components/ui/: - 0 hand-rolled buttons, inputs, notices and dialogs; - ≤ 3 distinct card looks (panel, list row, card); - ≤ 5 z-index values and ≤ 2 shadows; - 0 settings <style> blocks beyond layout.

    The script output goes into each migration PR description.
