# API keys (CLV-32)

Status: spec. Mockup: [mocks/clv-32/clv-32.html](mocks/clv-32/clv-32.html), PNGs `mocks/clv-32/png/a1.png` …
`a3.png`. Settings › Security. Copy follows the settings audit §5
([2026-10-30-settings-copy-audit.md](2026-10-30-settings-copy-audit.md)). MCP is CLV-33 and out of scope here.

## 1. Placement

A new `SettingsSection` **API keys** (`id="security-api-keys"`) in `SecuritySettings.vue`, right after
**Admin access** and before **Sealed mode**: both are about who may act as admin.

- Registry destination `security-api-keys`, label **API keys**. Keywords: "api", "api key", "token", "bearer",
  "home assistant", "script", "automation".
- Security subtitle: **Admin password · API keys · allowed sites**.
- Intro line under the title (`--fs-sm`, `--ink-2`): **Let apps and scripts, like Home Assistant, use Calvin
  without the admin password. Give each one its own key.**

## 2. Scopes

The three scopes are a ladder. Each one includes the one before:

| Scope | Label | Description (verbatim) |
|---|---|---|
| `read` | **Read** | See calendars, photos, settings and status. Can't change anything. |
| `admin` | **Admin** | Everything Read can, plus change settings and content, like signing in as admin. |
| `host` | **Host control** | Everything Admin can, plus restart Calvin, reboot this machine and install updates. |

**Backend note:** the UI assumes `host` ⊇ `admin` ⊇ `read`. Host actions also stay behind `CALVIN_HOST_CONTROL`
(`require_host_control`): a host key can't do more than the server allows. If the backend keeps `host` separate
(host routes only), the Host control description becomes **Only restart Calvin, reboot this machine and install
updates.** Nothing else changes.

**Host control looks dangerous on purpose:**
- Its option card has a 1px `--err` border once selected, `--err` 6% tint, and a ⚠ before the label.
- The description is followed by **Anyone with this key can reboot the machine Calvin runs on.** (`--err`, `--fs-xs`, 500).
- Selecting it adds a required checkbox under the cards: **I understand this key can reboot this machine.**
  **Create key** stays disabled until it's ticked. Changing the scope away clears the tick.
- **Unavailable** when `GET /api/system/environment` reports `host_control: false` (Docker, or the setting is off):
  - the card is disabled (`opacity: .55`, `aria-disabled`);
  - its description becomes **Not available: this Calvin doesn't control its machine.**;
  - it can't be selected.
  - While the environment is loading or unknown (null), the card stays enabled; the backend still refuses.

## 3. States

### 3.1 Empty (mock A1, left)

`EmptyState`-style block inside the section (no QR):
- **No API keys yet.**
- **Create one to let Home Assistant or a script read or change Calvin.**
- Button **Create key** (`.btn--primary`).

### 3.2 Create (mock A1, right)

**Create key** opens an inline form in the section (same pattern as Change password, not a modal: the OSK and
phone layouts already work there). It replaces the button; the list stays below.

- **Name** text field, required, max 40 characters, placeholder **Home Assistant**. Hint: **So you know which app
  uses it.** It must be unique (case-insensitive) among active keys. Error: **You already have a key called
  {name}.** Empty on submit: **Give the key a name.**
- **What it can do**: a `<fieldset>` with that `<legend>`. Three radio cards in a row (stacked under 600px), each
  ≥ 44px tall, with label + description from §2. Default selection: **Read**.
- The host checkbox (§2) when Host control is selected.
- Buttons: **Create key** (`.btn--primary`) and **Cancel** (ghost). While saving: **Creating…**, disabled.
- On a touch kiosk (`isTouch` and width ≥ 720), one hint line above the buttons: **Easier on the computer where
  you'll paste it: the key is only shown once.** It doesn't block anything.
- Errors: a failed POST shows **Couldn't create the key. Try again.** under the buttons and keeps the form. A 401
  opens the CLV-9 sign-in dialog, as everywhere.

### 3.3 Show once (mock A2)

After a successful create, the form is replaced by a result panel. Border 1px `--focus`, radius 12px, padding 1.25rem:
- Title **Copy your key now** (`--fs-md`, 600).
- **You won't be able to see it again. If you lose it, revoke it and create a new one.** (`--fs-sm`, `--ink-2`)
- The secret is in a read-only `<input>` (`--font-data`, 0.95rem, full width, `aria-label="New API key for {name}"`).
  It selects all on focus and on tap.
- **Copy** button beside it:
  - **Clipboard API available** (`navigator.clipboard` and a secure context): write the secret, then label
    **✓ Copied** for 2s, announced via `aria-live="polite"`: **Key copied.**
  - **Otherwise** (plain-HTTP LAN, the usual case): select the input and try `document.execCommand("copy")`. On
    success, the same **✓ Copied**. On failure, the button reads **Select and copy** and the hint
    **Press Ctrl+C (or long-press → Copy) to copy the selected key.** shows.
- A usage line (`--fs-xs`, `--ink-2`): **Send it as** `Authorization: Bearer <key>` (code style).
- **Done** (`.btn`). It discards the secret from memory and returns to the list with the new key at the top.
  Leaving the section or Settings also discards it. The secret is never put in the store, localStorage, the URL
  or logs.
- No QR code: a secret shouldn't sit on a wall screen as a scannable image.

### 3.4 List (mock A3)

One row per active key, newest first, as `SettingRow`s:
- Label: the key's **name**, followed by a scope chip:
  - Read and Admin: `--ink-2` text, 1px `--line`;
  - Host control: `--err` text, 1px `color-mix(in srgb, var(--err) 45%, var(--line))`, ⚠ prefix.
- Description: `{prefix}…` (`--font-data`, the first 8 characters the backend returns as `prefix`) ·
  **Created {date}** · **Last used {relative}** or **Never used**. Date format: "30 Oct", with the year if not the
  current year. Relative times: "just now", "12 min ago", "3 h ago", "2 days ago", then the date.
- Host key on a server without host control: the extra line **Host actions are blocked: this Calvin doesn't control
  its machine.** (`--ink-3`).
- Action: **Revoke** (`.btn`, `--err` text). Phone: the row stacks (`:stacked="isPhone"`).
- Below the rows: **Create key** (`.btn`) to open §3.2 again.
- Load failure: **Couldn't load API keys.** + **Try again**. Loading: three 3.5rem skeleton rows.

### 3.5 Revoke (mock A3, dialog)

`ConfirmModal`:
- title **Revoke "{name}"?**
- message **Apps using this key stop working right away. This can't be undone.**
- confirm **Revoke key** (`.btn-danger`), cancel **Cancel**.

On success, the row is removed and the live region says **{name} revoked.** On failure, the dialog closes and the
row shows **Couldn't revoke this key. Try again.** (`--err`, `--fs-xs`).

## 4. Data contract (for the backend lane)

- `GET /api/auth/keys` → `{ keys: [{ id, name, scope, prefix, createdAt, lastUsedAt | null }] }`. Never the secret
  or the hash.
- `POST /api/auth/keys { name, scope }` → `{ key: {…same…}, secret }`. The only time the secret is sent. 409 on a
  duplicate name, 422 for an unknown scope, 403 for `host` when host control is off.
- `DELETE /api/auth/keys/{id}` → 204.
- All three require an admin **session** (cookie), not a key: a key can't mint or revoke keys. Say so in the API
  docs; the UI needs no copy for it.
- `prefix` = the first 8 characters of the secret (e.g. `clv_7Hq2`), stored in clear for identification.

## 5. Accessibility

- The scope cards are a native radio group in a `fieldset`/`legend`, with arrow-key navigation. Disabled Host
  control is announced with its reason (its description is the `aria-describedby`).
- The host checkbox is a real `<input type="checkbox">` with its label.
- The result panel takes focus on its title (`tabindex="-1"`) so screen readers announce **Copy your key now**.
- Danger isn't colour-only: ⚠ and the explicit sentence carry it too.
- Touch targets are ≥ 44px (cards, Copy, Revoke). The on-screen keyboard works in the Name field (it's a normal
  text input).

## 6. Tests (vitest)

- Empty state renders and **Create key** opens the form.
- Form:
  - Name required, ≤ 40, and the duplicate-name error; default scope Read;
  - Host control shows the warning sentence and checkbox, and Create stays disabled until it's ticked;
  - switching scope clears the tick;
  - Host control is disabled with the "Not available" copy when the environment says `host_control: false`, and
    enabled when the environment is null.
- Create success shows the show-once panel with the secret, and focus moves to its title. **Done** clears it: the
  secret is no longer in the DOM or component state, and the list has the new key first.
- Copy: the clipboard path shows ✓ Copied and announces it; the execCommand fallback works; the double failure
  shows **Select and copy** and the Ctrl+C hint.
- List: the scope chip for each scope; the prefix, created and last-used formats (including "Never used"); the
  blocked-host line.
- Revoke: the confirm copy; confirm → DELETE, row removed, announced; failure → inline error.
- A 401 on any call opens the sign-in dialog; a create failure keeps the form values.
- No secret ever reaches localStorage, sessionStorage or the logger (spy on them).
