# Calvin app for Homey: UX and copy (calvin-gkdx)

Status: spec for the first version of the `calvin-homey` app (id `xyz.wholab.calvin`). It covers every word a person
sees in Homey: pairing, devices, flow cards, app settings and errors. The planning lane takes copy from here
verbatim; the string ids in §9 are suggestions it may rename.

Inputs:
- Research and the owner's approved choices: `docs/research/2026-11-19-homey-app.md` (branch `research/homey-app`).
  Each Calvin screen is a Homey device; `onoff` holds the screen on or off; held state is read-only and includes
  holds made in Calvin Settings; offline is an alarm; "back to schedule" is its own action; one app-level
  connection (address + `screens.power` key) entered at pairing; polling every 30 s; Homey Pro only; CLI install.
- Calvin's own words for the same things, so both apps say the same thing:
  - Settings › Screens: "Off, set by home automation. The schedule is paused." and **Back to schedule**.
  - The key option is **Turn screens on and off**, in **Settings › Security › API keys**.
  - The rule from [2026-10-31-no-developer-words.md](2026-10-31-no-developer-words.md): never say kiosk, API (except
    "API key", the name Calvin's Settings uses), backend, endpoint, instance or HTTP codes.
- Athom's rules: [App Store guidelines](https://apps.developer.homey.app/app-store/guidelines) and the SDK docs. The
  rules this spec relies on are listed in §10. Where Athom's docs are silent, the spec says so, and the planning lane
  checks it on the owner's Homey.

## 1. Voice

- **Calvin is the name of the server**, and **screen** is what a person calls each display. Homey calls them devices,
  so a screen added to Homey is a "screen" in our words and a device in Homey's chrome.
- Sentence case everywhere. Titles have no full stop; hints and messages are full sentences that end with one.
- Errors say what happened and what to do next, in that order. They never apologise and never show a status code,
  a key or a stack trace.
- Calvin's menu paths are written exactly as Calvin shows them, with ›: "Calvin › Settings › Security › API keys".
- Homey's flow card rules apply on top (§10): short titles, no device names, no parentheses, no When/And/Then.

## 2. Names and store text

| Item | Text | Rule |
|---|---|---|
| App name | **Calvin** | 1.1.1 brand name; 1.1.2 no "Homey"; 1.1.4 at most 4 words |
| Description (one line under the name) | **Turn your wall screens off when nobody's home, and on again when someone is.** | 1.2.2 one-liner; 1.2.3 not "Adds support for…" or "Control your X with…" |
| Driver name (shown when adding a device: Calvin › …) | **Screen** | |
| Device name at pairing | The screen's name in Calvin (`overrides.displayName`), else its id | People rename it in Homey as usual |
| Device class | `tv` (it exists in the SDK; its icon and voice-assistant type fit a wall display). Fall back to `other` if `tv` adds UI or voice behaviour that doesn't fit (check on the owner's Homey) | |
| `brandColor` | `#e08a1e` (Calvin's light-theme orange); the icons are white line art on it | 1.7 |
| App icon | A simple wall-mounted screen with a small clock line, white line art, 960×960 transparent vector, no fill | 1.5 |
| Driver icon | The same screen seen from the right-side angle, so it differs from the app icon | 1.6 |

**README.txt** (1.3: plain text, one or two paragraphs, no headings, no URLs, no feature list):

```
Calvin is a family dashboard for wall screens: calendars, photos and the things your household checks every day. This app adds each Calvin screen to Homey, so a flow can turn the screens off when everyone has left and on again when someone comes home, and you can see whether a screen is following its own schedule.

To connect, create a key in Calvin under Settings, Security, API keys, and choose Turn screens on and off. Then add a Calvin screen in Homey and paste the key. If you remove the app, revoke the key in Calvin too.
```

The README uses commas instead of › because the store shows plain text, and the › may not survive every font.

## 3. Pairing

Adding the first screen opens **Connect to Calvin**: one custom view with both fields, tested in one step, then
Homey's own **list_devices** view, then **done**. Later screens skip the connect view and go straight to the list,
because the connection is app-wide. A two-field view is shorter than one view per field, and the test needs both
fields anyway.

```
┌──────────────────────────────────────┐
│ Connect to Calvin                     │  ← Homey.setTitle
│                                       │
│ Calvin address                        │
│ [ http://calvin.local:8000         ]  │
│ The address you open Calvin at in a   │
│ browser, including the port.          │
│                                       │
│ Key                                   │
│ [ ••••••••••••••••••••          👁 ]  │
│ In Calvin: Settings › Security ›      │
│ API keys › Create key, then choose    │
│ Turn screens on and off. Calvin shows │
│ the key only once.                    │
│                                       │
│ <error line, if any>                  │
│                                       │
│              [ Connect ]              │
└──────────────────────────────────────┘
```

### 3.1 Connect to Calvin (custom view `connect`)

| Element | Text |
|---|---|
| Title | **Connect to Calvin** |
| Address label | **Calvin address** |
| Address placeholder | `http://calvin.local:8000` |
| Address hint | **The address you open Calvin at in a browser, including the port.** |
| Key label | **Key** |
| Key placeholder | (none) |
| Key hint | **In Calvin: Settings › Security › API keys › Create key, then choose Turn screens on and off. Calvin shows the key only once.** |
| Show-key toggle (icon button, accessible name) | **Show key** / **Hide key** |
| Button | **Connect**; while testing, the button reads **Connecting…** and is inactive |

Behaviour and messages, in check order. Each message appears in the error line above the button, in the view's error
colour, and focus moves to the field it names. Use `Homey.alert` only for the last row.

| Check | Message under the form |
|---|---|
| Address empty | **Enter Calvin's address.** |
| Address has no `http://` or `https://` | Add `http://` silently and carry on. Only if the result is still invalid: **Enter an address like http://calvin.local:8000.** |
| Key empty | **Paste the key from Calvin.** |
| Calvin doesn't answer (timeout or refused connection) | **Couldn't reach Calvin at {address}. Check the address and port, and that Calvin is on the same network as Homey.** |
| An https:// certificate isn't trusted | **Couldn't check Calvin's certificate. Use an address with a certificate your devices trust, or http:// on a network you trust.** |
| Something answers, but it isn't Calvin (no screen list in the answer) | **Something answered at {address}, but it isn't Calvin. Check the port.** |
| Calvin is older than the app needs (§7 says how to tell) | **This Calvin is too old for the Homey app. Update Calvin, then try again.** |
| The key is refused | **Calvin didn't accept this key. Check that it's complete, or create a new one in Calvin.** |
| Anything else | `Homey.alert`: **Couldn't connect to Calvin. Try again in a moment.** |

The key is tested with the screen list read sent with the key: a wrong or revoked key gets refused on any route
(research §3). Once a "who am I" read exists (research step 8), add one more check after the key is accepted: an
admin key shows a warning that doesn't block, **This key can change all of Calvin's settings. A Turn screens on and
off key is safer.**, with the buttons **Use it anyway** and **Change key**.

The address shown in a message is the one the person typed. The key never appears in any message, log or view after
this one.

### 3.2 Choose screens (system view `list_devices`)

- Title, if the template takes one: **Choose screens**. The view's own title isn't documented; if Homey shows its
  default, leave it.
- One entry per Calvin screen not yet in Homey: the screen's Calvin name. Entries are not filtered by online state.
  An offline screen can still be added, and it shows the offline alarm until it checks in.
- No screens in Calvin: throw **Calvin has no screens yet. Set one up in Calvin, then add it here.**
- Every screen already added: throw **Every Calvin screen is already in Homey.**
- Calvin unreachable between connect and list (rare): throw the "Couldn't reach Calvin at {address}…" line from §3.1.

The thrown text is what Homey shows; its layout isn't documented, so keep each message to one sentence or two short
ones.

### 3.3 Repair (on any Calvin screen)

Repair uses the same `connect` view, so people learn one form.

| Element | Text |
|---|---|
| Title | **Change Calvin connection** |
| Note above the fields | **This changes the address and key for every Calvin screen in Homey. Your flows keep working.** |
| Address | prefilled with the saved address |
| Key | empty, hint as in §3.1; the saved key is never shown |
| Button | **Save**; **Saving…** while testing |
| Errors | as in §3.1 |
| Success | Homey closes the view. Every screen comes back available on the next poll, run at once. |

Repair can't bring back a screen that was removed from Calvin: that device's message (§7) tells the person to delete
it.

## 4. Devices: what Homey shows

### 4.1 Capabilities

| Capability | What it means | Title | Shown as |
|---|---|---|---|
| `onoff` (system) | On = Calvin plans the screen to be on now (`desiredOn`): its schedule, or a hold. Setting it holds the screen on or off | Homey's own (don't override) | The device tile's on/off state and toggle |
| `calvin_held` (custom, boolean, read-only) | Calvin's `held`: the screen is held on or off and ignores its schedule. True for holds from Homey, other home automation, or Calvin Settings | **Schedule**, with `titleTrue` **Paused** and `titleFalse` **Running**. If Homey shows Yes/No for a custom boolean instead, use the title **Schedule paused** | Sensor row on the device |
| `alarm_calvin_offline` (custom, boolean) | Calvin hasn't heard from the screen for 2 minutes | **Offline** | Homey's alarm indicator on the tile (warning icon; red in the sensor list) |
| `button.back_to_schedule` (maintenance action) | Sends the screen back to its schedule | **Back to schedule**; `desc` **Ends the hold. The screen turns on and off by its own schedule again.** | Device settings › Maintenance actions |

Insights (Timeline) titles:

| Capability | `insightsTitleTrue` | `insightsTitleFalse` |
|---|---|---|
| `onoff` | **Screen turned on** | **Screen turned off** |
| `calvin_held` | **Schedule paused** | **Schedule running** |
| `alarm_calvin_offline` | **Screen went offline** | **Screen came back online** |

All titles stay within Athom's 2 to 3 words for capability titles.

### 4.2 States

| Situation in Calvin | Tile | Schedule | Offline | Message on the device |
|---|---|---|---|---|
| Following its schedule, on | On | Running | — | — |
| Following its schedule, off (night) | Off | Running | — | — |
| Held off by a Homey flow | Off | Paused | — | — |
| Held on in Calvin Settings by a person | On | Paused | — | — |
| Screen not heard from for 2 minutes | last planned state | as is | **Offline** alarm | — (changes still work: Calvin keeps them and the screen applies them when it's back) |
| Screen software too old to hold | as Calvin reports | as is | — | Warning: **This screen needs a software update in Calvin › Settings › Screens. Until then, its next scheduled change undoes Homey's on or off.** |
| Calvin unreachable, key refused, screen removed, Calvin too old | — | — | — | The device is unavailable with the §7 message |

Notes:
- **On means "planned on", not "lit".** Calvin can't see the panel. A screen that is held off and then woken by a
  touch stays lit while Homey shows Off (bead calvin-dcfs). The README for power users says so; the device doesn't.
- The warning uses the SDK's `Device#setWarning`. Athom's guides don't describe it (it's in the SDK reference only),
  so check on the owner's Homey that the text shows on the device. If it doesn't, drop it: the hold still works until
  the next scheduled change.
- Who set a hold (Homey or Calvin Settings) isn't shown in v1. Calvin's own Settings shows it.

### 4.3 Turning a screen on or off from Homey

- Tap, voice or flow sets `onoff`. The app sends the hold and sets the tile from Calvin's answer at once, not on the
  next poll.
- If Calvin refuses or can't be reached, the listener throws, and Homey shows the text from §7 and puts the tile
  back.

## 5. Flow cards

Homey's built-in `onoff` cards (turn on, turn off, toggle, is on, turned on, turned off) come for free with their
own titles. The app adds the cards below. Every device card takes the screen as its only argument, using Homey's
device picker (`filter: driver_id=screen`); the app cards take no arguments. That is the whole argument list in v1.

### 5.1 Triggers (When)

| Id | Title | Hint |
|---|---|---|
| `calvin_held_true` | **The schedule was paused** | **The screen was held on or off, from Homey or from Calvin Settings.** |
| `calvin_held_false` | **The schedule resumed** | **The screen went back to its own schedule.** |
| `alarm_calvin_offline_true` | **Went offline** | **Calvin hasn't heard from the screen for 2 minutes.** |
| `alarm_calvin_offline_false` | **Came back online** | **The screen is in touch with Calvin again.** |

With polling, these fire up to 30 seconds after the change. The hints don't say so; the README does.

### 5.2 Conditions (And)

| Id | Title (inverted form after the bar) | Hint |
|---|---|---|
| `schedule_paused` | **The schedule !{{is|isn't}} paused** | **Paused means the screen is held on or off, from Homey or from Calvin Settings, until something sends it back to its schedule.** |
| `is_offline` | **!{{Is|Isn't}} offline** | **Offline means Calvin hasn't heard from the screen for 2 minutes.** |

### 5.3 Actions (Then)

| Id | Kind | Title | Hint |
|---|---|---|---|
| `back_to_schedule` | device | **Go back to schedule** | **Ends a hold from Homey or from Calvin Settings. The screen then follows its own schedule.** |
| `all_on` | app | **Turn all screens on** | **Holds every Calvin screen in Homey on, until something changes it.** |
| `all_off` | app | **Turn all screens off** | **Holds every Calvin screen in Homey off, until something changes it.** |
| `all_back_to_schedule` | app | **Send all screens back to schedule** | **Every Calvin screen in Homey follows its own schedule again.** |

Wording choices:
- The device action is an instruction ("Go back to schedule"), as Athom's examples are ("Lock door"). The
  maintenance button keeps Calvin's own button text, **Back to schedule**.
- "All screens" means the screens added to Homey, not every screen Calvin has; the hints say so.
- An app action that partly fails throws **Couldn't change {n} of {total} screens. Check the Calvin screens in
  Homey.** The screens that worked stay changed.

Flow run errors (shown in the flow's run log) are the §7 action texts.

## 6. App settings (Homey › Apps › Calvin › Configure)

Athom prefers pairing and repair for credentials, and research §2 left the page out. The brief asks for "change
address or key" there too, because that's where people look first. So there is one small page, using the same
fields, checks and messages as §3.1, so there's one way to fix a connection.

| Element | Text |
|---|---|
| Page title | **Calvin connection** |
| Status line | Connected: **Connected to Calvin. {n} screens in Homey.** (1 → **1 screen in Homey.**). Not connected: the current §7 problem in one line. No connection yet: **Not connected yet. Add a Calvin screen to connect.** |
| Address | label **Calvin address**, the saved value, hint as §3.1 |
| Key | label **Key**; shows the key's first characters only, **clv_ab12…** (Calvin's prefix display), and a **Change key** button that reveals an empty Key field with the §3.1 hint |
| Button | **Save**; **Saving…** while testing; success line **Saved. Connected to Calvin.** |
| Errors | §3.1 messages, under the form |
| Footer note | **If you remove this app, revoke its key in Calvin › Settings › Security › API keys.** |

The page never shows the full key, and nothing on it reveals the key again.

## 7. Errors a person can see

Two places show errors. **Unavailable** marks the device, through `setUnavailable(message)`. Athom's guide shows it
without a message, but the SDK reference takes one; check that Homey shows it. **Thrown** errors appear where a tap
or flow fails.

| Cause | How the app tells | Unavailable message (every affected screen) | Thrown when a tap or flow acts |
|---|---|---|---|
| Calvin unreachable | 3 polls in a row fail (about 90 s), so a restart doesn't flap the tiles | **Can't reach Calvin. Homey keeps trying every 30 seconds.** | **Couldn't reach Calvin. Try again when it's back.** |
| Key refused or revoked | A refusal from Calvin with the key (one is enough; polling stops until repaired) | **Calvin no longer accepts the key. Repair this screen to enter a new one.** | **Calvin no longer accepts the key. Repair the screen to enter a new one.** |
| Screen removed from Calvin | Calvin says that screen is unknown | **This screen was removed from Calvin. Delete it here, or set it up in Calvin again.** (only this device) | same text |
| Calvin too old | Calvin's screen list lacks the hold fields (`powerHold`, `agentHolds`), or the screen-power read is missing. The planning lane picks the exact check | **Calvin needs an update for this app. After the update, the screens come back by themselves.** | same text |
| Too many changes | Calvin's limit of 30 changes a minute | — | **Too many changes in a minute. Try again in a moment.** |
| Anything else on an action | | — | **Couldn't change the screen. Try again.** |

- An offline screen is never unavailable (research §2): its alarm shows, and holds still go through.
- When the cause clears, the next poll makes the devices available again with no message. A key problem clears
  only through repair or app settings.
- The app logs the cause for its own log in plain words too, never with the key. The address stays out of the
  logs as well (research §7).

## 8. Later versions, so v1 leaves room

- **Pairing code** (before the App Store): the connect view's Key field becomes **Code from Calvin** with the hint
  **In Calvin: Settings › Screens › Connect Homey. The code works for 5 minutes.**, using Homey's `pincode` view.
  Pasting a key stays as a **Use a key instead** link.
- **Discovery** (mDNS, before the App Store; Athom rejects typed addresses when discovery could work): the connect
  view opens on **Calvin found on your network: {name}** with **Use this Calvin** / **Enter an address instead**.
- **Event stream**: no copy change; triggers just fire within a second.
- **Who set the hold**, if Calvin exposes it: a second sensor row would show "Held by Homey" or "Held in Calvin". Not
  now.

## 9. Languages and string ids

- **v1 is English only.** Every string is an `{ "en": "…" }` translation object in the compose files (driver,
  capabilities, flow cards). Custom views (connect, app settings) use `Homey.__("…")` keys in `locales/en.json`.
  Homey falls back to English for a missing key.
- **Where Dutch slots in:** add `"nl"` beside every `"en"` in the compose files, a `locales/nl.json` with the same
  keys, and `README.nl.txt`. Athom rule 1.11.2: if one card is translated, translate all cards, capabilities and
  settings for that language, so a language ships complete or not at all. Calvin's own menus stay in English
  ("Settings › Security › API keys"), so a Dutch string names them in English. Homey's other languages (de, fr, it,
  sv, no, es, da, ru, pl, ko, ar) slot in the same way.
- Suggested `locales/en.json` keys: `connect.title`, `connect.repair_title`, `connect.repair_note`,
  `connect.address_label`, `connect.address_hint`, `connect.key_label`, `connect.key_hint`, `connect.show_key`,
  `connect.hide_key`, `connect.button`, `connect.button_busy`, `connect.save`, `connect.save_busy`,
  `error.address_empty`, `error.address_invalid`, `error.key_empty`, `error.unreachable`, `error.certificate`,
  `error.not_calvin`, `error.too_old`, `error.key_refused`, `error.unknown`, `settings.*` for §6. Device and flow
  texts live in the compose files beside their ids (§4, §5).
- Messages with values use Homey's `__name__` placeholders: `"Couldn't reach Calvin at __address__. …"`.
