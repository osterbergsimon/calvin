# Highlight holidays (calvin-xlyk)

Status: **proposal, awaiting the owner's approval.** Nothing here is built until the owner approves the
direction (§1). Mock: [mocks/holidays/index.html](mocks/holidays/index.html), frames S1…P1, with PNGs in
`mocks/holidays/png/`.

Builds on:
- the [display settings per region](2026-10-30-display-settings-per-region.md) spec, which puts holidays with
  the household settings in **Content › Calendar basics**;
- the [frontend doctrine](frontend-doctrine.md) and the [no-developer-words](2026-10-31-no-developer-words.md)
  rules.

## 0. Today

- `showRedDays` exists in config (default `false`), and `CalendarView.vue` adds `.red-day` when it is on. But
  `isRedDay()` always returns `false`, so nothing is ever highlighted.
- The **Highlight holidays** toggle is no longer in Settings: `ContentSettings.vue` has no row for it. The
  setting exists only in the config.
- `.red-day` gives the cell a 10 % `--err` tint and `--err-text` on the day number. It has never shown.

## 1. The direction (for the owner)

1. **The household picks a country, and optionally a region.** That one choice turns holidays on. There is no
   separate on/off toggle: **Off** is the first entry in the country list.
2. **Holiday dates come from the Calvin server**, from an offline library (Python `holidays`), so no network is
   needed. Days are counted in the household time zone. The server design (the coordinator's) owns the call
   and the data. This page only lists what the UI needs (§7).
3. **A holiday shows in red on the calendar, with its name.** The day number is red, as on a printed calendar,
   and the name goes on the day's header line. A holiday also gets the weekend tint, because it is a day off.
4. **Names are in English** where the library has an English name, and otherwise in the country's own
   language. This is an open question for the owner (§9).

## 2. Settings: Content › Calendar basics (S1-S3)

Two rows go after **Weekend days** and before **Time format**. They sit next to the other "what our week looks
like" settings.

### 2.1 Holidays

`SettingRow`, label **Holidays**, description **Marks public holidays on the calendar, with their names.**

- **Control:** `SelectPill`, `searchable`, `search-label="Search countries"`, `aria-label="Holidays"`.
  - The first option is **Off** (value `null`).
  - Then every country the server lists, by English name, sorted alphabetically (for example **Sweden**).
- **Suggestion.** While it is Off, and the household time zone maps to exactly one listed country, add a second
  option **{Country} (your time zone)**, right under Off. For example, with `Europe/Stockholm`: **Sweden (your
  time zone)**.
  - Choosing it saves that country.
  - The suggestion is never chosen automatically.
- **Saving:** at once, through the existing config save, like the other rows in this section. There is no
  Saved line, as in the rest of Calendar basics.

### 2.2 Region (only when the country has regions)

`SettingRow`, label **Region**, description **Some holidays are only kept in part of the country.**

- **Control:** `SelectPill`, `searchable` when there are more than 10 options,
  `search-label="Search regions"`, `aria-label="Region"`.
  - The first option is **Whole country** (value `null`).
  - Then the country's regions, by the library's name for each, sorted.
- The row appears only after a country is chosen, and only when the server lists regions for it. Changing the
  country resets the region to **Whole country**.
- Focus stays on the Holidays pill when the Region row appears. Nothing moves focus.

### 2.3 Off, and an old server

- **Off:** no Region row. The calendar shows no highlight and no names, and asks the server for nothing.
- **The server can't list countries** (an old server, or a failed request): both rows are hidden. Nothing
  else changes.
- **Settings search** (`settingsRegistry.js`): an entry **Holidays** under Content › Calendar basics, with the
  keywords `holidays`, `public holidays`, `red days`, `bank holidays`, `country`, `region`.

## 3. The calendar (D1-D4, P1)

A holiday is a date in the household time zone. The calendar asks the server for the holidays in the dates it
shows, and asks again when the dates change, the country or region changes, or the day turns.

### 3.1 Month view, including rolling (D1, D2)

- **The day number** uses the holiday ink: `--holiday-ink`, a new component token equal to
  `var(--err-text)`, declared in `theme.css` beside the other component tokens. It is the one sanctioned
  red-as-meaning outside status, and it is named so the doctrine's "status colours never decorate" lint can
  allow exactly this token. Weight `--weight-title`, as `.red-day .day-number` already sets.
  - Declare `--holiday-ink: var(--err-text)` on **the same selectors that set `--err-text`** (every theme and
    dark block), not only on `:root`. A custom property's `var()` resolves where it is declared, so a
    `:root`-only alias keeps the light red in dark themes (the mock showed exactly that).
- **The background:** the weekend tint (`.weekend`), not the 10 % `--err` wash. A wall of pink cells across a
  holiday week reads as an error. Remove the `.red-day` background rule.
- **The name:** in `.day-header`, after the number, on the same line.
  - `--text-dense` (the calendar-grid role), `--holiday-ink`, one line, ellipsis when it doesn't fit.
  - The full name is in the element's `title`.
  - Example: `25  Christmas Day`.
  - It takes no event row, because the header line is already there.
- **Two holidays on one date:** the names are joined with **" · "**, and the ellipsis cuts as usual.
- **Today is a holiday:** today's border, tint and number colour win. The name keeps the holiday ink, so the
  holiday still shows.
- **Days outside the month** (dimmed): no highlight and no name, as the current `:not(.other-month)` rule
  does.
- **Phone width** (`(--bp-phone)`, the compact calendar, P1): the red number only, with no name, because the
  cells are too narrow. The name is still in `title`, and in the week and day views.

### 3.2 Week strip (agenda) and day view (D3, D4)

- **Week strip:** each column's header (`.day-header`) has the red number and the name under it, at
  `--text-caption`, up to two lines, then an ellipsis.
- **Day view:** the date header line gets **· {name}** in `--holiday-ink`, for example `Thursday 25 December ·
  Christmas Day`.

### 3.3 Screen readers

- A holiday's day header gets a visually hidden **, {name}** after the date, and the visible name is
  `aria-hidden`, so it is read once: "25, Christmas Day".
- The colour is never the only signal, because the name is there in every view except the phone month view.
  There the `title` and the hidden text carry it.

### 3.4 Themes and contrast

- `--err-text` is a text colour in every theme. Check `--holiday-ink` with the CLV-64 contrast test on `--bg-1`,
  on the weekend tint and on today's tint (`--focus` 12 %), in the 5 themes × light/dark.
- With the light and Backlit tokens, the ink reaches 9.4:1 and 8.7:1 on `--bg-1`, 9.1:1 and 8.3:1 on the weekend
  tint, and 8.4:1 and 6.9:1 on today's tint.

### 3.5 Loading and errors

- **While the dates load:** no highlight. Holidays appear when the answer comes, with no animation.
- **A failed request:** no highlight and no message. Holidays are a hint, not a feature. The next date change
  tries again.
- **Offline:** use the last answer cached for those dates (`fetchWithCache`), and otherwise show none.

## 5. The old setting

- `showRedDays` goes from the config, the schema and `configRegistry.js`. `CalendarView.vue` reads the country
  instead: a country set means on.
- There is nothing to migrate, because the old switch never did anything. A household that had it on starts
  at Off. It sees the new row the first time it opens Calendar basics.
- Keep the `.red-day` class name, so existing theme CSS that targets it still applies.

## 6. What the builder must not do or guess

- **Don't add an on/off toggle** beside the country. Off is a country choice (§1.1).
- **Don't pick a country automatically**, including from the time zone (§2.1).
- **Don't use `--err` or `--err-text` directly** for holidays. Use `--holiday-ink`, and only for the holiday
  number and name.
- **Don't tint the cell red** (§3.1), and **don't add an event chip** for a holiday: it isn't an event.
- **Don't show an error** for a failed holiday request (§3.5).
- **Don't fetch holidays from the browser** or any outside service: the server answers.
- **Don't say** "subdivision", "ISO", "locale", "library" or "API" in copy.

## 7. What the UI needs from the server (for the server design)

- A list of countries: code and English name. For each country, its regions: code and name.
- Holidays for a date range, for the household's country and region, in the household time zone: date and name.
  When there are two holidays on one date, both come back.
- The config keys for the country and the region. Both are `null` when holidays are off.

## 8. Tests the builder adds

- **Settings:**
  - Off hides Region;
  - a country with regions shows Region with **Whole country** first;
  - a country without regions hides it;
  - changing the country resets the region;
  - the time-zone suggestion shows only while Off and saves that country;
  - both rows are hidden when the country list fails.
- **Calendar (unit):**
  - a holiday date gets `.red-day` and its name in the header;
  - two names are joined with " · ";
  - other-month days get neither;
  - today and a holiday together keep today's styles and show the name;
  - at phone width the name is not rendered visibly but is in `title`;
  - a failed request shows nothing and logs nothing on the dashboard.
- **Copy guard:** `noDevWords.spec.js` passes.
- **Playwright (mocked routes):** month view at 800×480 and 390, and week strip at 800×480, light and Backlit,
  with a holiday week. Attach the screenshots to the PR (doctrine §7).
