# dd9.4 — Per-kiosk content assignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let each kiosk be assigned which screens it may show (`availableScreens`) and which it boots into (`defaultScreenId`), and make the runtime active screen local-per-kiosk in Mode B (so switching on one kiosk no longer changes all of them).

**Architecture:** The two keys are per-kiosk override keys carried by dd9.3's effective-config endpoint (backend only types them on `ConfigUpdate`). The frontend reads them into dedicated store refs in kiosk mode, seeds a local `kioskActiveScreenId` that survives config polls, exposes an `effectiveDashboardScreens` computed (filtered + active-overridden) that components consume, and branches the screen-switch actions so kiosk mode updates local state instead of persisting global.

**Tech Stack:** Vue 3 + Pinia + Vitest (frontend), FastAPI + Pytest/`uv` (backend). Project ruff is 0.14.11 (`uv sync --extra dev`; run `uv run ruff check .`/`format --check .`). Frontend lint: `npm run lint` (eslint). Frontend tests need `node_modules` — if absent in the worktree, symlink `/home/tux/code/calvin/frontend/node_modules` into `frontend/` and do NOT commit it.

## Global Constraints

- **Kiosk mode = `getKioskId() != null`** (reuse `frontend/src/utils/kioskId.js`). Mode A = no kiosk id.
- **Mode A is byte-for-byte unchanged**: active screen stays in global `dashboardScreens.activeScreenId`; switches still call `updateConfig({ dashboardScreens })`.
- **Shallow, top-level**: `availableScreens`/`defaultScreenId` are plain override keys (dd9.3 merge). The global screen catalog is never forked.
- **Never render an empty/invalid screen** — fail open: empty/invalid `availableScreens` ⇒ treat as all.
- `availableScreens: list[str] | None` (absent ⇒ all). `defaultScreenId: str | None`.
- Seed precedence for the kiosk's initial active screen: `defaultScreenId` → global `dashboardScreens.activeScreenId` → first available.
- After a route change, regenerate OpenAPI snapshot + `types.ts` (`cd backend && UPDATE_OPENAPI_SNAPSHOT=1 uv run pytest tests/contract/test_openapi_snapshot.py`; `cd frontend && npm run gen:api`). (Adding optional `ConfigUpdate` fields changes the `OverridesBody`→`ConfigUpdate` schema → snapshot updates.)

```javascript
// Per-kiosk content assignment (calvin-dd9.4).

// Intersect a screens config's screens[] with an allowlist (catalog order).
// Fails open: null/empty allowlist, or an empty intersection, returns all screens.
export function filterAvailableScreens(screensConfig, availableIds) {
  const normalized = normalizeDashboardScreens(screensConfig);
  if (!Array.isArray(availableIds) || availableIds.length === 0) return normalized;
  const allow = new Set(availableIds);
  const screens = normalized.screens.filter(screen => allow.has(screen.id));
  if (screens.length === 0) return normalized; // fail open
  return { ...normalized, screens };
}

// Resolve which screen a kiosk should show. Precedence:
//   still-valid `current` → valid `defaultScreenId` → global activeScreenId → first available.
export function resolveKioskActiveScreen({ screensConfig, availableScreens, defaultScreenId, current }) {
  const filtered = filterAvailableScreens(screensConfig, availableScreens);
  const ids = new Set(filtered.screens.map(screen => screen.id));
  if (current && ids.has(current)) return current;
  if (defaultScreenId && ids.has(defaultScreenId)) return defaultScreenId;
  if (filtered.activeScreenId && ids.has(filtered.activeScreenId)) return filtered.activeScreenId;
  return filtered.screens[0]?.id ?? null;
}
```
