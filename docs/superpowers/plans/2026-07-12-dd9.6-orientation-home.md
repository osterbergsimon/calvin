# dd9.6 — Orientation home (Mode-A guard) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Gate the backend's startup orientation sync so it only runs when a local X display is present — so remote (Mode-B) backends skip it cleanly instead of pointlessly running `xrandr` and logging a warning every boot.

**Architecture:** dd9.6 is a *decision* issue; the per-kiosk orientation storage/serving already shipped in dd9.3 (orientation is a `ConfigUpdate` field + in `DEVICE_PHYSICAL_KEYS`). The only code change is a one-line guard in `_sync_display_orientation` (`backend/app/main.py`) using the existing `has_x11()` helper. Two follow-up issues are filed by the controller (not code).

**Tech Stack:** FastAPI, Python 3.12+ / `uv`, Pytest, Loguru. Project ruff is 0.14.11 (`uv sync --extra dev`; `uv run ruff check .` / `format --check .` must be clean).

## Global Constraints

- **Do not remove** `display_orientation_service` or the `orientation`/`orientationFlipped`/`applyDisplayRotation` global-config defaults — Mode A relies on them.
- The guard uses the existing `has_x11()` from `app.utils.platform` (returns `bool`). No new config/env flag.
- When no local display: skip at **`debug`** level (not `warning`), return early, do NOT call `display_orientation_service`. When a display is present: existing behavior unchanged.
- Loguru, not stdlib logging.

### Task 1: Mode-A guard on `_sync_display_orientation`

**Files:**
- Modify: `backend/app/main.py` (`_sync_display_orientation`, ~line 336)

**Interfaces:**
- Consumes: `has_x11()` from `app.utils.platform` (existing, returns `bool`).
- Produces: `_sync_display_orientation()` returns early (no service call) when `has_x11()` is False.

- [ ] **Step 1: Write the failing tests**

Create `backend/tests/unit/test_sync_display_orientation.py`:

```python
"""Unit tests for the Mode-A guard on the startup orientation sync (calvin-dd9.6)."""

from unittest.mock import AsyncMock, patch

import pytest

from app.main import _sync_display_orientation


@pytest.mark.asyncio
@pytest.mark.unit
async def test_skips_when_no_local_display():
    """No local X display (Mode B) => return early, never touch the orientation service."""
    with (
        patch("app.utils.platform.has_x11", return_value=False),
        patch(
            "app.services.display_orientation_service.display_orientation_service.sync_with_config",
            new=AsyncMock(),
        ) as sync,
    ):
        await _sync_display_orientation()
    sync.assert_not_called()


@pytest.mark.asyncio
@pytest.mark.unit
async def test_runs_sync_when_local_display_present():
    """A local X display (Mode A) => proceed to the existing sync path."""
    with (
        patch("app.utils.platform.has_x11", return_value=True),
        patch(
            "app.services.config_service.config_service.get_value",
            new=AsyncMock(return_value=True),
        ),
        patch(
            "app.services.display_orientation_service.display_orientation_service.sync_with_config",
            new=AsyncMock(return_value={"success": True, "message": "ok"}),
        ) as sync,
    ):
        await _sync_display_orientation()
    sync.assert_called_once()
```

- [ ] **Step 3: Add the guard**

In `backend/app/main.py`, at the top of `_sync_display_orientation()` (after the docstring, before the existing `from app.services.config_service import ...` imports), add:

```python
    from app.utils.platform import has_x11

    if not has_x11():
        # Mode B (remote/display-less backend): the device-side display-agent owns
        # orientation. Skip the backend-local xrandr sync instead of failing on it.
        logger.debug("No local X display; skipping backend orientation sync (device-side agent owns it)")
        return
```

The rest of the function (the `apply_rotation` / `sync_with_config` / try-except block) stays exactly as-is.
