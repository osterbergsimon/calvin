# dd9.3 — Server-side per-kiosk config store + merged `/api/config` — design

- **Date:** 2026-07-12
- **Status:** Approved (brainstorm), pending implementation plan
- **Issue:** `calvin-dd9.3` (epic `calvin-dd9`)
- **Base branch:** `develop` (this design lives on `feature/dd9.3-per-kiosk-config`)
- **Builds on:** dd9.2 (kiosk identity). The whole-epic model is in
  [2026-07-11-per-kiosk-settings-model-design.md](2026-07-11-per-kiosk-settings-model-design.md);
  this doc pins the dd9.3-specific decisions.

## Problem

dd9.2 gave each kiosk a stable identity and a registry (`kiosks` table with an unused
`overrides` JSON column + `last_applied_version`, and `GET /api/kiosks`). Today
`GET /api/config?kiosk=<id>` only *records* the kiosk — it returns the global config
unchanged (the handler literally comments "per-kiosk merge arrives in dd9.3"). This slice
adds the per-kiosk **config layer**: a way to store sparse overrides per kiosk, a merged
read so each kiosk gets `global + its overrides`, and a cheap version signal the (future)
display-agent will poll to know when to re-apply device-physical settings.

## Goals

- Store a sparse **per-kiosk override layer** and read/write it via a dedicated resource.
- `GET /api/config?kiosk=<id>` returns **`shallow-merge(global, overrides[id])`**.
- Expose a **`deviceConfigVersion`** (ETag + body field) so a client can detect device-physical
  changes without diffing full config.
- **Backward compatible:** no `kiosk` param ⇒ today's exact global response; a kiosk with no
  overrides ⇒ merged response byte-identical to global.

## Non-goals (deferred)

- **The display-agent apply loop** (read device-physical from merged config, `xrandr`/backlight,
  `If-None-Match` fast-poll, POST back `last_applied_version`) — its own later slice, merges
  with dd9.1. This slice is **server-side only**, fully testable with API tests, no Pi needed.
- **Content-assignment fields** (`availableScreens`, `defaultScreenId`) — dd9.4. They are just
  more override keys and need no new mechanism here.
- **Per-kiosk write UI** — a later slice once the whole backend is done.

## Design

### 1. Storage — reuse `KioskDB.overrides`

The `overrides` JSON column already exists (dd9.2). It holds a **sparse dict of config
fields**, e.g. `{"orientation": "portrait", "displayScheduleEnabled": true}`. No migration
needed. `null`/absent ⇒ no overrides.

### 2. Write path — `/api/kiosks/{kiosk_id}/config` (decision A)

A dedicated resource for the override layer, keeping the global-write contract on
`/api/config` clean (dd9.2 deliberately kept `POST /api/config` = global).

- **`GET /api/kiosks/{kiosk_id}/config`** → `{"id": <id>, "overrides": {...}}` — the raw
  stored override layer (NOT merged). `404` if the kiosk id is unknown. `400` if the id fails
  the shape check (reuse `_KIOSK_ID_RE` = `^[A-Za-z0-9._-]{1,64}$` from `kiosk_registry`).
- **`PUT /api/kiosks/{kiosk_id}/config`** with body `{"overrides": { ... }}` → **replaces**
  the whole override layer (idempotent PUT; the editor does read-modify-write). `PUT {"overrides": {}}`
  clears all overrides. **Upserts** the kiosk row if the id is new (allows pre-provisioning a
  kiosk before it first connects). `400` on invalid id shape or malformed body. Wrap the write
  with `retry_on_db_locked` (house rule).
- **Validation of override keys:** the body is a sparse object validated by the existing
  `ConfigUpdate` Pydantic model (`extra="allow"`, so unknown keys pass but declared keys are
  type-checked). Reject a payload that isn't a JSON object. Cap the serialized size (e.g. reject
  `> 64 KB`) so the column can't be stuffed. Do **not** hand-maintain a per-kiosk allowlist —
  the UI controls which fields it exposes; storing an extra sensible key is harmless.

### 3. Merged read — `GET /api/config?kiosk=<id>`

Extend the existing handler. After it builds the fully-defaulted global `config` dict (as
today) and records the kiosk, look up the kiosk's `overrides` and apply a **shallow top-level
merge** (decision A): for each key in `overrides`, `config[key] = overrides[key]` (override
wins, including over defaults). No recursion, no array merging. Then attach the version (below).

- No `kiosk` param → skip entirely → unchanged global response (regression-guarded).
- `kiosk` present but unknown / no overrides → merged == defaulted global (byte-identical).
- The merged response **includes device-physical values** (rotation, schedule, future
  brightness/output) — they are served, not stripped. The agent reads them; the browser
  ignores the ones it can't act on in Mode B (it already ignores rotation there).

### 4. `deviceConfigVersion` — ETag + body field

A cheap signal for "did this kiosk's device-physical settings change?".

- **`DEVICE_PHYSICAL_KEYS`** — a module constant naming the keys that a device-agent applies:
  `orientation`, `orientationFlipped`, `applyDisplayRotation`, `displayScheduleEnabled`,
  `displaySchedule` (current), plus reserved future keys `displayBrightness`, `displayOutput`,
  `displayResolution` (harmless if absent). One place to extend as dd9.1 follow-ups land.
- **Version** = short hex of `sha256(json.dumps({k: merged.get(k) for k in DEVICE_PHYSICAL_KEYS}, sort_keys=True, default=str))`.
  Stable (sorted keys) → same inputs ⇒ same version; any device-physical change ⇒ new version.
  Non-device-physical config changes (theme, time format) do **not** bump it.
- Exposed two ways on `GET /api/config?kiosk=<id>`:
  1. as an **`ETag`** header, with **`If-None-Match` → `304 Not Modified`** support (the future
     agent fast-polls cheaply);
  2. as a **`deviceConfigVersion`** field in the response body (so any client can read it
     without inspecting headers).
- The unscoped `GET /api/config` (no kiosk) does **not** get an ETag (unchanged contract).

### 5. Service layer

Add to `app/services/kiosk_registry.py` (it already owns kiosk rows):
- `async get_overrides(kiosk_id) -> dict | None` — the raw layer, `None` if kiosk unknown.
- `async set_overrides(kiosk_id, overrides: dict) -> None` — upsert row + replace overrides
  (wrapped in `retry_on_db_locked`).
- `def device_config_version(merged: dict) -> str` — pure hash helper (unit-testable).
- `def merge_overrides(global_config: dict, overrides: dict | None) -> dict` — pure shallow
  merge (unit-testable, no DB).

Keeping merge + version as **pure functions** means the interesting logic is tested without a
DB or HTTP, and the route/handler just wires them.

## Data flow

```
Browser / display-agent
  └─ GET /api/config?kiosk=hallway-3f9a2c   [If-None-Match: <etag>?]
        └─ record_kiosk(hallway-3f9a2c)          (dd9.2, best-effort)
        └─ config = defaulted global             (existing)
        └─ overrides = get_overrides(id)         (new)
        └─ merged = merge_overrides(config, overrides)   (shallow)
        └─ version = device_config_version(merged)
        └─ If-None-Match == version ? 304 : 200 + ETag + body{..., deviceConfigVersion}

Kiosks UI (future) / API client
  └─ GET /api/kiosks/{id}/config  → { id, overrides }
  └─ PUT /api/kiosks/{id}/config  { overrides:{...} }  → upsert + replace
```

## Backward compatibility

- No `kiosk` param ⇒ handler skips the override/version block ⇒ identical to today (regression
  test).
- Registered kiosk with `overrides == None`/`{}` ⇒ merged == defaulted global (byte-identical
  except the added `deviceConfigVersion` field + ETag, which only appear on the scoped path).
- `POST /api/config` stays global-only (unchanged). New behavior is isolated to the new
  `/api/kiosks/{id}/config` resource and the scoped GET.

## Testing strategy

- **Unit (pure, no DB):** `merge_overrides` — override wins, sparse keys fall through, empty/None
  overrides == global, top-level only (a nested key replaces wholesale). `device_config_version`
  — stable for same inputs; changes when a device-physical key changes; unchanged when a
  non-device-physical key changes.
- **Service:** `get_overrides` (unknown → None), `set_overrides` (upsert new kiosk; replace
  semantics; clear via `{}`).
- **Integration:** `PUT` then `GET /api/kiosks/{id}/config` round-trips; `GET /api/config?kiosk=<id>`
  reflects overrides; **no-kiosk response unchanged** (regression); unknown-kiosk merged == global;
  `ETag` present on scoped GET and `If-None-Match` returns `304`; invalid id → 400; oversized body
  → rejected; `POST /api/config` still writes global (not a kiosk).

## Open questions

None blocking. Deferred by design: the display-agent apply loop (own slice), content-assignment
override keys (dd9.4), and the write UI (later). The `deviceConfigVersion` surface here (ETag +
body field) is deliberately enough for the agent slice to consume without adding a dedicated
version endpoint now.
