# Device-local output + resolution via the display-agent — design

- **Date:** 2026-07-13
- **Status:** Approved (brainstorm), pending implementation plan
- **Issue:** `calvin-dd9.1` (Tier 1: device-local display settings via `/etc/default/calvin-kiosk` + display-agent)
- **Base branch:** `develop` (this design lives on `feature/dd9.1-device-display`)
- **Builds on:** the shipped rotation path (dd9.9) — `apply_device_physical` / `apply_rotation` in
  `deploy/kiosk-agent/calvin_display_agent.py`, gated on `deviceConfigVersion`.

## Problem

In Mode B (central server + dumb kiosks) the backend cannot run local `xrandr`, so device-physical
display settings are applied on the Pi by the display-agent. Rotation already works this way. This slice
extends the same pattern to the two remaining **xrandr-applied** settings — **which output is primary** and
**screen resolution/mode** — so an operator can set them per-Pi without SSH. Brightness (a different
mechanism: backlight sysfs / ddcutil) is a separate follow-on.

## Design principle

Mirror the shipped rotation path exactly — same dual source (device-local env var wins over server config),
same `deviceConfigVersion`-gated apply, same one-shot-at-startup + on-change trigger, same
monkeypatched-subprocess test idiom. Add small, independently tested apply functions; do not restructure the
agent. No backend changes are required: `displayOutput` and `displayResolution` are already members of
`DEVICE_PHYSICAL_KEYS` (`backend/app/services/kiosk_registry.py`), so the version hash already covers them.

## Locked context (verified in develop)

- `apply_device_physical(cfg, *, applier=apply_rotation, env=None)` runs when `deviceConfigVersion` changes
  (and once at startup via `main()`); it currently resolves the target output from `CALVIN_DISPLAY_OUTPUT`
  and applies rotation via `apply_rotation(rotation, output=None)` → `["xrandr", "--output", out, "--rotate",
  rotation]`, auto-detecting the output with `detect_primary_output()` when none is given.
- `cfg_get(cfg, "snake_case", "camelCase", default=…)` reads both key spellings.
- `CALVIN_DISPLAY_ROTATION` env wins over server `orientation`; `CALVIN_DISPLAY_OUTPUT` env supplies the
  output name. Both are read from `/etc/default/calvin-kiosk` (systemd `EnvironmentFile`).
- `DEVICE_PHYSICAL_KEYS` already includes `displayOutput`, `displayResolution` (and `displayBrightness`,
  reserved for the brightness follow-on).
- Tests live in `deploy/kiosk-agent/test_display_agent.py` (pytest, pure stdlib): they monkeypatch
  `agent.subprocess.run` to capture the command list and assert the exact `xrandr …` argv, and inject
  `fetch`/`sleep`/`iterations`/`apply_device`/`applier` for the loop and apply seams.
- There is **no** `setup-kiosk.sh`; the env file is documented in `docs/setup/DEPLOYMENT_TOPOLOGIES.md`.

## Keys + precedence

| Setting | Server key (camelCase / snake) | Env override (`/etc/default/calvin-kiosk`) | Value format |
|---|---|---|---|
| Primary output | `displayOutput` / `display_output` | `CALVIN_DISPLAY_OUTPUT` (already read) | xrandr output name, e.g. `HDMI-1` |
| Resolution/mode | `displayResolution` / `display_resolution` | `CALVIN_DISPLAY_RESOLUTION` (new) | `WIDTHxHEIGHT` or `WIDTHxHEIGHT@RATE`, e.g. `1920x1080` or `1920x1080@60` |

Precedence for each setting (mirrors rotation): **env override → server config → (output only) auto-detect**.
An absent/empty value means *skip that setting and leave the hardware as-is* — never force a default.

## Apply

Extend `apply_device_physical` to, on each device-physical apply:

1. **Resolve the target output** once: `CALVIN_DISPLAY_OUTPUT` env → server `displayOutput` →
   `detect_primary_output()`. Call this `out`.
2. **Apply output + mode first** (before rotation), via a new `apply_mode(output, resolution)`:
   - Parse `resolution`: split on `@` into `mode` (e.g. `1920x1080`) and optional `rate` (e.g. `60`). The
     `mode` must match `^\d+x\d+$`; `rate` (if present) must be a positive number. If `resolution` is set but
     malformed, log a warning and skip the mode (do not run xrandr with a bad argument).
   - Build argv:
     - resolution present + valid: `["xrandr", "--output", out, "--primary", "--mode", mode]` (+ `["--rate",
       rate]` when a rate was given);
     - output configured but no resolution: `["xrandr", "--output", out, "--primary"]`;
     - neither configured: do nothing (return a skip marker).
   - Run it with the existing `X11_ENV`; a non-zero exit or exception is logged and swallowed (returns a
     skip/failure marker) — it must not raise out of `apply_device_physical`.
3. **Apply rotation last** via the existing `apply_rotation(rotation, output=out)`, so rotation wins if a
   mode change reset it.

Setting an output (env or server) marks it `--primary`. This is a deliberate, documented extension of
today's behavior, where `CALVIN_DISPLAY_OUTPUT` only *targeted* rotation; under this design, configuring the
output also *selects it as primary* — which is the dd9.1 goal ("which HDMI output is primary").

`apply_mode` returns a small result (the applied argv, or a skip/failure marker) so the loop can log it,
mirroring how `apply_rotation` returns the output name or `None`.

## Error handling

- Malformed `resolution` (fails the `WxH[@RATE]` parse) → warn + skip the mode; still apply output-primary
  and rotation.
- xrandr non-zero / raises (unknown output, unsupported mode) → warn + skip; the loop continues and retries
  on the next device-config change. A failing mode apply must never crash `run()` or blank the screen (the
  agent's existing resilience contract — covered by a test).
- Absent output *and* absent resolution → no xrandr call for this feature (rotation path unchanged).

## Data flow

```
deviceConfigVersion changes (or startup) → apply_device_physical(cfg, env):
    out = CALVIN_DISPLAY_OUTPUT | cfg.displayOutput | detect_primary_output()
    res = CALVIN_DISPLAY_RESOLUTION | cfg.displayResolution
    apply_mode(out, res):   xrandr --output out --primary [--mode WxH [--rate R]]   (parse-guarded, error-safe)
    apply_rotation(rotation, output=out):   xrandr --output out --rotate …          (unchanged, runs last)
```

## Testing strategy

Add to `deploy/kiosk-agent/test_display_agent.py` (pytest, monkeypatch `agent.subprocess.run` to capture
argv), mirroring the rotation tests:

- `apply_mode` builds `["xrandr","--output","HDMI-1","--primary","--mode","1920x1080"]` for `("HDMI-1",
  "1920x1080")`.
- `@RATE` variant appends `["--rate","60"]` for `1920x1080@60`.
- output-only (`resolution=None`) → `["xrandr","--output","HDMI-1","--primary"]`.
- neither output-config nor resolution → no xrandr mode call (skip marker), rotation path untouched.
- malformed resolution (`"1080p"`, `"1920x"`, `"1920x1080@x"`) → no `--mode` argv, warning path, no raise.
- xrandr returns non-zero for the mode → `apply_mode` returns a failure marker and does **not** raise.
- precedence: `CALVIN_DISPLAY_RESOLUTION` env wins over server `displayResolution`; `CALVIN_DISPLAY_OUTPUT`
  env wins over server `displayOutput`.
- ordering: within one `apply_device_physical`, the mode xrandr call is captured **before** the rotate call.
- version-gating unchanged: `apply_device_physical` still fires once at startup and on
  `deviceConfigVersion` change, not on unrelated config changes (existing tests keep passing).

All tests pure-stdlib; run with `pytest deploy/kiosk-agent/test_display_agent.py`.

## Docs

In `docs/setup/DEPLOYMENT_TOPOLOGIES.md`, extend the `/etc/default/calvin-kiosk` env-key documentation to
list `CALVIN_DISPLAY_OUTPUT` (output name, marks it primary) and `CALVIN_DISPLAY_RESOLUTION`
(`WxH` / `WxH@RATE`), noting env overrides server config and that both are applied by the display-agent via
xrandr at startup and on change.

## Non-goals (follow-ons)

- **Brightness** (backlight sysfs / `ddcutil`) — a different, hardware-variable mechanism that can black out
  a panel; its own slice. File as a dd9.1 follow-on.
- **A per-kiosk UI** for output/resolution in the Kiosks settings view — the server keys already exist;
  authoring UI is a later slice (like the orientation/content editors).
- **Multi-output / multi-screen** mapping (one Pi driving several outputs with different content) — that is
  dd9.5.
- **Refresh-rate discovery / validation against `xrandr` modes** — v1 passes the mode/rate through and lets
  xrandr reject invalid combinations (logged, skipped); it does not pre-validate against available modes.

## Open questions

None blocking. The env+server dual-path (mirroring rotation) and marking the configured output `--primary`
were approved in brainstorming.
