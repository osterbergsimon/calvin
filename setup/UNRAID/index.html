    Unraid Deployment¶

    Run Calvin on Unraid as the backend, then point one or more Raspberry Pis at it as kiosk-only displays.

    What runs¶
    Image ghcr.io/osterbergsimon/calvin:develop (public, amd64 + arm64 + arm/v7)
    Built from the develop branch: every push to develop publishes a new :develop image. Releases are published from vX.Y.Z tags (see RELEASING.md).
    Port 8000 (UI and API on the same port)
    Data /mnt/user/appdata/calvin → /var/lib/calvin (database, images, plugins, themes, kiosk signing key)
    Runs as PUID=99 / PGID=100 (Unraid's nobody:users)
    Timezone the Unraid server's (Settings → Date and Time); Unraid passes TZ to every container itself, so the template has no TZ field

    Install¶

    1. Fetch the template once from a terminal on the Unraid box (Terminal icon in the top bar of the web UI):
    wget -O /boot/config/plugins/dockerMan/templates-user/my-Calvin.xml \
  https://raw.githubusercontent.com/osterbergsimon/calvin/develop/deploy/unraid/calvin.xml
    1. Open the Docker tab.
    2. Click Add Container at the bottom, then pick Calvin from the Template dropdown (under User templates).
    3. Leave the defaults unless you need to change them:
    4. WebUI Port 8000. Change this if port 8000 is already taken.
    5. Appdata /mnt/user/appdata/calvin.
    6. Public URL: the address phones and new kiosks should use, for example http://192.0.2.10:8000 (the Unraid server's LAN IP and the WebUI port). The container can't detect it itself; without it, the "set up from your phone" QR codes and the Add kiosk install command show the container's internal IP whenever Calvin is opened via localhost.
    7. Advanced view: PUID 99 and PGID 100. The paths and the database URL normally stay as they are; keep the plugin directory inside /var/lib/calvin.
    8. Click Apply. Unraid pulls the image and starts the container.

    Open Calvin at:

    http://<unraid-host>:8000/

    If it doesn't load, check http://<unraid-host>:8000/api/health, which should return {"status":"healthy"}. The Docker tab also shows the container's health, which comes from the image's built-in health check.

    Update¶

    Calvin tracks develop. Each push to develop builds and publishes a new :develop image (about 20 minutes after the push). To pick it up:

    1. In Docker, click Check for Updates.
    2. When Calvin shows update ready, click apply update.

    Unraid pulls the new image and recreates the container. Everything in appdata stays, including installed plugins. Their Python packages are re-installed automatically when the container starts.

    The container never controls the Unraid host. Calvin's reboot, backend/frontend restart, update and display-power actions are refused inside Docker, and CALVIN_HOST_CONTROL does not override that; use the Docker tab above for updates and restarts. See Host control.

    To stay on a known-good build, change Repository to a pinned tag. The template ships :develop because it is the only tag that exists before the first release; once a vX.Y.Z release is out, use that (or :latest):

    ghcr.io/osterbergsimon/calvin:v0.1.0

    Every published build also gets a sha-<commit> tag; the tag list is at https://github.com/osterbergsimon/calvin/pkgs/container/calvin. To go back to following develop, switch the tag back to :develop. A pinned release only moves when you change the Repository tag — Check for Updates finds nothing new on the same tag.

    Plugins¶

    Install plugins from Settings → Plugins as usual. Installing is live: plugin files go to appdata/calvin/plugins, their pip dependencies are installed into the running container, and no rebuild or restart is needed.

    Raspberry Pi kiosk¶

    Once Calvin is running on Unraid, turn a fresh Raspberry Pi OS Lite install into a kiosk with one command (the container serves the installer):

    curl -fsSL http://<unraid-host>:8000/api/kiosks/install.sh | sudo bash

    For a signed kiosk, the signing key is /mnt/user/appdata/calvin/kiosk-signing.key. It is in Appdata, so it survives container updates. Copy the key and the installer to the Pi over SSH instead of using the line above. KIOSK_INSTALL.md has the exact commands, plus a bake-the-SD-card option with no SSH at all.

    Use a stable hostname or IP for <unraid-host> so the kiosk URL does not change. To update a Pi's display agent later, use Settings → Screens → Update: the Unraid container serves the kiosk bundle that matches its own build. See Kiosk agent self-update.

    Backups¶

    Everything Calvin needs is under /mnt/user/appdata/calvin. Back it up with the rest of your appdata (for example with the Appdata Backup plugin).

    /mnt/user/appdata/calvin/kiosk-signing.key signs kiosk updates. It is the key that manifest signing calls <data dir>/kiosk-signing.key; read it with cat /mnt/user/appdata/calvin/kiosk-signing.key. If you lose it, a new key is generated, and every kiosk that has the old key baked in must be given the new one.

    Security¶

    Calvin has no built-in authentication. Do not expose the container to the internet. Keep it LAN-only, or put it behind a VPN or an authenticating reverse proxy.
